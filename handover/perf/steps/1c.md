## Commits

- **d289300 Keep saved definitions when a snapshot has none to keep (item 5).** Reproduced with an integration test: index a commit with code, index one with only a `.txt` file, index the first again: it was parsed again. `prune(keeping:)` now does nothing for an empty set.
- **ff9c4df Save definitions under the ID of the contents read, and never a failed read (item 6).** Reproduced with sources whose key names other bytes than they read (the hash-then-read race), and one whose first read fails: the first cached `written`'s definitions under `hashed`'s ID, the second cached `[]` forever. Now `ContentAnalysis.definitions(of:)` hashes the bytes it read (`blobID(of:)`) and saves under that key. A source asked for under git's ID but read as other bytes is returned under the asked key and saved under its own. It checks the saved definitions for the read key before parsing, so worktree files whose filters change them (autocrlf, LFS) are re-read and hashed each time, but never re-parsed. A read that returns nil is neither saved nor returned. Too large or binary contents are saved as `[]`, since they're named by their bytes. `Source.read` now returns raw bytes; the size and binary rule moved from DefinitionIndex to `ContentAnalysis.largestFile`/`isParseable`.
- **af9b6b7 Check #lua-match? and #has-ancestor? in queries (item 7).** `LuaPattern` (SextantCore/LuaPattern.swift, no SwiftTreeSitter) is a port of `lstrlib.c`'s matcher: classes, sets, the four quantifiers, anchors, captures and back references, `%b`, `%f`, plain-text patterns, as LuaJIT runs them. Neovim runs LuaJIT, which has `%g` and Lua 5.1 doesn't. It has 92 unit cases whose expected results come from LuaJIT itself, and malformed patterns return nil. A one-off differential run of 20,000 random patterns × texts against LuaJIT (scratch, not committed) gave 0 differences. 19,018 results matched exactly, and 729 patterns LuaJIT errors on are rejected. 253 more hold a bad back reference that LuaJIT never reached for that text; we reject those upfront, and LuaJIT found no match in any of them, so the predicate result is the same. `CheckedQuery` (QueryChecks.swift) wraps each SwiftTreeSitter query and filters matches by two-capture `#eq?`/`#not-eq?`, `#lua-match?`/`#not-lua-match?` and `#has-ancestor?`/`#not-has-ancestor?`, for highlights, tags and locals. Highlights didn't check two-capture `#eq?` before; Haskell's highlights use it. Tests on the real grammars: before, every Zig identifier was coloured type and constant, and every CMake argument constant. Julia's `#has-ancestor?` coloured `begin` as a built-in outside indexing. Cost: PageList.zig (720 KB) tokens 323 → 347 ms in release, and 128k → 51k tokens.
- **38ab8fc Show when git can't give a worktree's status (item 3).** `Git.status()` in SextantCore throws; tested with a conflicted repo (count, conflicts) and a damaged index (throws). Repository keeps `statusFailures` per worktree. **What the user sees:** the picker row says "Status unavailable", the commits list's Uncommitted row shows a warning symbol with git's message as its tooltip, and the review summary says "Couldn't read what isn't committed: <git's message>". Conflict marks keep their last known value, since unknown isn't none.
- **ca765d3 Name every repository and worktree root as realpath does (item 2).** `CanonicalPath` (SextantCore) is the one type: `realpath(3)` (which also corrects case), and for a path that's gone, its deepest existing part resolved and the rest kept. `Git.Location.root/commonDir`, `Worktree.root`, `Subject.worktree`, `Repository.commonDir`, the review and notes stores, status maps and `FileWatcher(paths:)` all take it. `FileWatcher` moved to SextantCore (takes a queue; the app wraps its handler in `MainActor.assumeIsolated`; the stream owns the handler, so no callback can reach a freed watcher). The refresh filter is `RepositoryChanges.matter(_:)`, a pure function, which now also ignores `worktrees/<id>/logs`. Tests: `/tmp` → `/private/tmp`, a repository through a symlink, `Git.locate` from a subfolder of a symlinked path, and a real FSEvents run through a symlink checking how each path is classified.
- **1256ee7 Refresh for lock files a project tracks, ignoring only git's own (item 1).** Lock files are ignored only inside the common git directory or a `/.git/` folder. Tested as a pure table and with real FSEvents (`git add Cargo.lock` writes `index.lock`).
- **9a3dfe8 Give Find and definition lookups their own tasks (item 4).** `findTask` owns the Find list (Find in Files, Find References, Jump's no-definition fallback, which cancels it). `definitionTask` owns Jump to Definition and Peek. A newer request for the same place cancels the older one.
- **b9121b7 Automation: `nowait <command>`, and `statusFailures` in the dump.** Needed to reproduce item 4 (every command waits for idle) and to see item 3.
- **b652c62 Leave a pane on its file when a refresh changes only other files (lead).** Under the same target and commits, a pane whose FileState is unchanged is left as it is. A file opened outside the review is re-read and kept if its blob ID is the same.
- **d587c53 Stop a window's searches, loads, indexing and timers when it closes (lead).** Closing cancels the refresh, find and definition tasks, each session's indexing and loads, the after-frame timers, and each reader's analysis. Closing a pane stops its reader too.
- **111b2a8 Compare with the usual base once a saved base's branch is gone (lead).** A saved base counts only while it names a branch; `load` also replaces a review's base that no longer exists, so a refresh after `git branch -d` doesn't quietly compare with nothing.

## What didn't hold
- **Item 2 overstated:** uncommitted and conflict lookups did match. Every worktree root came from git (`--show-toplevel`, `worktree list`), which already gives realpaths. Only `commonDir`, built from `--git-common-dir` relative to the path opened, was wrong, so the self-refresh was real and the lookups weren't affected.
- **Item 3 can't be shown on the reviewed worktree itself:** every way I found to fail status (damaged index) fails the diff too. An unreadable folder only warns, and a broken submodule fails the diff but not status. So it shows up in the picker and for other worktrees.
- **Reload lead:** selection and caret were already put back, and blame came back because it was re-run. What was lost was Highlight Uses, plus a wasted blame and re-render.
- **Lifetimes lead:** the first run showed nothing because Linux's definitions were cached. With `.git/sextant` removed (as the suite's reset does), indexing ran on for 104 CPU-s after close.

## Leads checked, for later steps
- **`#is-not? local` holds (step 6):** SwiftTreeSitter's `isNot` always passes, so every Ruby identifier, locals included, is coloured as a method call (checked), and JS/TS/TSX/Nix colour shadowed `console`, `require` and the like as built-ins. A fix needs the locals scopes during highlighting, which step 6's single pass computes anyway. `#has-ancestor?` and two-capture `#eq?` in highlights held and are fixed.
- **ContentAnalysis lost saves still holds (step 7):** `saveSoon` returns early until `load()` runs, and only `definitions(of:)` calls `load()`, so reading-only sessions never save definitions.
- Not done from Argon's lifetimes finding: the `ReviewStore`/`NotesStore` static caches never evict, `idleWaiters` is static, RevisionSheet can be submitted twice, and a running git process isn't killed on cancel (Git.run, steps 2/4).
- The reader's own analysis still keys a worktree file's lines by the hash-object ID; `Git.diff`'s mtime retry guards that race. Step 6's "store hashes what it analyses" should cover it.

## What the next step must know
- Roots are `CanonicalPath` everywhere; build any new path comparison on it, and `RepositoryChanges` for event classification (step 4). `Subject.key` and saved-base keys use the canonical path: a hard cutover, which only orphans bases saved for repositories once opened through a symlink.
- `FileWatcher` is in SextantCore and can run on any queue; tests drive it with real FSEvents (`RepositoryPathTests`), so step 4's watcher work can be tested the same way.
- `ContentAnalysis.Source.read` returns raw bytes or nil; the store decides parseability and the key. Indexing now SHA-1s every blob it reads (about 1 GB/s, small next to parsing).
- `CheckedQuery` is the seam step 6 replaces; `LuaPattern` stays.
- Scripted app checks for these fixes are in `scratch/perf/step1c/gui/repro.sh` (uncommitted); `nowait` makes concurrency bugs reproducible.
- Commits are unsigned: 1Password signing isn't reachable from these sessions (as in earlier steps).
