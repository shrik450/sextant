## The design: where state lives now

- **`FileState`** (shared by the session's panes, `Session.changes`/`explored`): `diff`, `isChange`, `reviewed`, `conflicted`, `hasLanguage`, `hunks: FileText` (made from the diff at init), `whole: FileText?` (set once, by `loadWhole(git:)` or `offerWhole`), and the read task. `wholeOrHunks`. `isTwoSided`, `isGenerated`. It never changes a text in place, and loading whole changes no pane.
- **`FileText`** (immutable lines, shared by every pane showing it): `lines`, `isWhole`, `gapsBefore`, and everything worked out from the lines, once, for every pane: tokens, definitions, outline, hasTags, changed words, names (`occurrences`), keyed runs. Everything that takes or returns a line index is here: `index(ofLine:old:)`, `lineNumber(at:) -> SideLine?`, `reference`, `folds(unfolded:keeping:)`, `anchor(of:)`, `run(at:)`. No version counter: results can't go stale. For an added/deleted/no-hunk file `hunks === whole`.
- **`ShownFile`** (a pane's own, `Reader.files`): the `FileState`, the `FileText` the pane shows, and the runs it `unfolded`. The pane's rows, caret, selection, scroll, kept positions, boxes and uses index its own texts; `Reader.position(of:inFile:)` and `sideLine(at:)` convert between line numbers and the pane's indices, which is what the window controller, inspector, jump bar and actions now use. `focusedFile` is a `ShownFile`; the inspector holds the focused pane's `ShownFile`.
- Which text: `Reader.text(of:)` = `wholeOrHunks`, picked at every layout (`pickTexts` in `reload`). When a file's text changes under a pane, its unfolds reset and the top line, caret and landed caret move by line number to the new text. Session-level: review state. Pane-level: text choice, unfolds, showAll/split/wrap, caret, scroll.

For **step 3**: a text never changes, so its rendered lines can be cached by `FileText` identity and folds, and `replaceTextStorage` reloads can reuse them; a review toggle changes only `reviewed`/read keys, never a text, so it can recolour without re-laying out (rows still point at the same lines). `pickTexts` is the one place a layout's texts can change. For **step 6**: `FileText.analyze` already analyses blob sides through `ContentAnalysis` by blob ID; a store keyed by blob ID can make whole texts (old blob + hunks) and their analysis, and hunk texts' tokens could come from a whole text's when one exists (today the overview parses hunk texts separately, as before).

## Leads checked

- **toggleShowAll clobbering the caret: held.** With the top on an unchanged line, hiding unchanged lines reopened that run (and remembered it as unfolded) and put the caret on line 1 (`showall` on 111b2a8: 2 folds, caret b.swift:1). Fixed in 2d79489 (3 folds, caret b.swift:303). I didn't clear `unfolded` when hiding again, as Argon suggested: the toggle goes back to the folds the reader had.
- **prepareWhole blocking open() on neighbour parses: held (by reading the code; not measured).** `open()` awaited the neighbour's load task, which only set the whole lines after both sides parsed. `loadWhole` now only reads; neighbours analyse after (`await f.whole?.analyze(symbols: true)`), and a pane showing the text joins that analysis instead of waiting for it.
- **isTwoSided false for one-sided modifications: held** (`columns`: 1 column on 111b2a8, 2 after).
- **reference / lineNumber(at:) crash on an empty file: didn't hold as a reachable crash.** `lineNumber(at:)` could trap on no lines, but every caller guarded or passed a `.line` row's index, which only exists for non-empty texts; `reference` filters indices. It now returns nil, so callers can't forget. The other half of Argon's Finding 7 (reference dropping removed lines when a context line is selected) is a 1e lead and isn't done.

## Decisions (for the user)

1. **All Changes shows a file read whole as the whole file, with or without Show Unchanged Lines** (97bd80f), rather than the orchestrator's "showAll off → hunks" (a7d32a8). On main the overview always showed files already read whole that way, folded unless unchanged lines show, so a fold's pill and Show Nearby Unchanged Lines opened runs in place; and the first change is read whole as a review opens. "Off → hunks" lost that, and the overview benchmark's unfold beeped. To go back: `Reader.text(of:)` returns `overview && !showAll ? f.hunks : f.wholeOrHunks`, and the shared scene's two fold/gap expectations flip.
2. Hiding unchanged lines again keeps the runs the reader unfolded (no clearing).
3. A caret a fold hides goes to the nearer line beside the fold.
4. `scenes.sh` doesn't check beeps or "came forward" as the harness does; I watched the logs instead.

## What the next step must know
